# Recuperación de sesiones de Claude Code — 2026-06-17

Un crash de la sesión GNOME (host-starvation) mató 4 sesiones de Claude Code.
Esta hoja tiene los comandos exactos para retomarlas.

## Antes de empezar

- **Esperá a que termine el backup de Déjà Dup** antes de levantar varias
  sesiones pesadas. El backup compite por CPU/IO y puede volver a starvar el
  host; levantar 4 sesiones de Claude Code encima de un backup activo es
  justo el escenario que disparó este crash.
- Los `claude --resume` son **interactivos**: corrélos vos en una terminal,
  uno por uno. No los lances en batch.
- El launcher (`linux/claude-code-multi-backend/claude-code-vertex`) ya quedó
  arreglado en la rama `fix/claude-launcher-orphan-recovery-symlink`: ahora la
  fuente de sesiones cerradas/huérfanas del selector encuentra estos transcripts
  (los 3 `find` sobre `projects/` usan `-L`, porque `~/.claude-andres/projects`
  es un symlink a `~/.claude/projects`). Si preferís el menú interactivo en vez
  de los comandos de abajo, podés lanzar el launcher, elegir "Retomar sesión
  existente" y buscar el UUID en la lista `[cerrada]`.

## Formato de cada comando

```bash
cd <cwd-de-creación>
CLAUDE_CONFIG_DIR=$HOME/.claude-andres claude --resume <UUID>
```

El `cd` importa: `claude --resume` resuelve la sesión por el mapeo
`cwd → ~/.claude/projects/<dir-codificado>`. Desde el directorio equivocado
falla con "No conversation found".

El worktree original `doj-4790-defer-onboarding` fue **limpiado** (borrado),
pero el branch `andres/doj-4790-defer-onboarding` **sigue vivo**. Hay que
recrear el worktree antes de retomar, para que el `cwd` exista de nuevo y el
`--resume` encuentre la sesión.

```bash

cd /home/kvttvrsis/Documentos/GitHub/dojocoding/dojo-os
git worktree add .claude/worktrees/doj-4790-defer-onboarding andres/doj-4790-defer-onboarding

# 2) Retomar desde el worktree recreado
cd /home/kvttvrsis/Documentos/GitHub/dojocoding/dojo-os/.claude/worktrees/doj-4790-defer-onboarding
CLAUDE_CONFIG_DIR=$HOME/.claude-andres claude --resume 9ce151c3-3666-426d-8871-9c641317d47e
```

> Nota: el `cwd` de creación que el launcher mapea es la ruta del worktree.
> Si el `git worktree add` la crea en una ruta distinta a la original, el
> `--resume` puede no encontrar la sesión; en ese caso el launcher recrea el
> directorio original (vacío) y avisa. Verificá que la ruta del paso 2 sea la
> misma donde corría la sesión antes del crash.
